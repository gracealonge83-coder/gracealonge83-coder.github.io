# Portioned — Private Beta Testing Case Study

**Project type:** Application testing and QA  
**Programme:** UriBuild Private Beta  
**Testing period:** 28 October–10 November 2026  
**My role:** Private beta participant and product tester

## Project overview

Portioned is a budgeting application. I joined its private beta to learn the product, work through assigned test activities and document my observations. My role is testing and feedback, not application development.

## Testing activities

My test activities have included:
- Reviewing profile setup and profile information.
- Checking opening balances, overview totals and decimal amount handling.
- Entering expenses and checking required-field validation.
- Exploring recurring expenses shared across multiple practice profiles.
- Checking how portions are allocated and how balances and activity records change.
- Comparing affected profile balances and overview totals after transactions.

## Examples of observations recorded

During testing, I documented observations for product-team review, including:
- A rounding display that was not clearly explained during one balance check.
- A change in the Total Available figure that I recorded for follow-up.
- An incorrectly created practice profile that did not have an available delete option.

These are tester observations, not claims that the product team has confirmed software defects.

## My testing approach

For each activity, I follow the assigned scenario, enter fictional practice data, check the resulting screen or records, compare the result with the expected behaviour and record the outcome. I distinguish between a passed check, an observation and an issue that needs further clarification.
